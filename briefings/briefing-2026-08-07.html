Agent Engineering & AI SDLC
1. Agent Plugins — the packaging layer above MCP
MomentumExplosive SentimentPositive Production ReadyMedium Hype RiskLow ConfidenceHigh
What is happening

A vendor-neutral package format (spec v1.0.0 published July 24; broader rollout Aug 6) from a TSC of Amazon, Cursor, Microsoft, OpenAI, Vercel, with Google joining as core maintainer Aug 6. A plugin is a directory with a plugin.json manifest that bundles Agent Skills + MCP servers. Notably absent: Anthropic, which created both MCP and Agent Skills.

Why it matters

As Google's post puts it: "the core problem isn't the components, it's the manifest." Skills and MCP servers were each already portable; the box you put them in wasn't — every client invented its own directory layout, metadata shape, and transport inference. This is the npm/OCI moment for agent extensions: package once, run in any compliant client (Kiro, VS Code, Cursor). The spec deliberately scopes to packaging/discoverability only — it does not touch marketplaces, permissions, or runtime.

Evidence from real teams

AWS Agent Toolkit already compatible; Kiro rolling out support. Spec developed in public on GitHub. Hooks/sub-agents on the roadmap for future versions.

Engineering implication

Stop hand-rolling per-client packaging for your MCP servers and skills; adopt the plugin.json layout now to avoid the fork-and-drift tax. The Anthropic absence is a governance watchpoint, not a blocker. Verdict: Adopt the packaging convention; track permission/marketplace layers as they come.

2. Harness engineering — now staffed, benchmarked, and productized
MomentumExplosive SentimentPositive Production ReadyHigh Hype RiskLow ConfidenceHigh
What is happening

The orchestration wrapper around an LLM (tool loop, context rendering, state, retries, verification, memory) is now a first-class, named, staffed layer across independent vendors. DeepSeek's Harness beta drew 712 open-source projects in four days; DeepSeek runs an explicit "Model + Harness = Agent" team (Cui Tianyi, ex-Jane Street). Snowflake's data-eng-bench shows a data-native harness (CoCo + Opus 5) solves 73.8% Pass@1 / 64.1% Pass^3 vs generic Claude Code/Codex at lower cost. Prime Intellect's Prime Agent open-sources a harness where sub-agents are first-class.

Why it matters

Same frontier model, different harness, order-of-magnitude cost and quality deltas — repeatedly. The harness, not the model, is the unit of optimization and the unit of vertical specialization (data-native, security-native, cost-disciplined).

Evidence from real teams

Snowflake CoCo (data), DeepSeek Harness (coding/agent), AlphaSense (finance: 3x cheaper, 2:1 preferred vs raw vector RAG), Cursor planner-worker swarm (22x worker cost cut), Microsoft MDASH (security). Now productized across >5 independent vendors in one week.

Engineering implication

Invest harness-engineering headcount, not just model selection; treat your tool loop/context/state layer as versioned infrastructure with its own evals. Build a vertical-specific harness for your domain rather than defaulting to a generic coding agent. Verdict: Adopt.

3. Agent red-teaming as a system (AgentBreaker)
MomentumHigh SentimentPositive Production ReadyMedium Hype RiskMedium ConfidenceMedium
What is happening

At Black Hat 2026, NVIDIA researchers released AgentBreaker, an open-source scanner that maps an agent's attack surface (purpose + tools + per-tool scope), then runs a four-stage attack loop (map→search→exploit→adapt) with multiple attacker LLMs and "recommender" LLMs after each failure. Crucially it tests agents as systems — tools and access, not just the underlying LLM.

Why it matters

Cost per run is 75–125x lower than frontier-API red-teaming using a fine-tuned open model (GLM-5.2-NVFP4, the same quantized open model Hugging Face reached for after guardrailed Claude/Opus refused incident-response queries), with fewer refusals and self-hosted data privacy. Brings agent red-teaming from ~$100k/run toward ~$1k.

Evidence from real teams

NVIDIA (tool authors); Hugging Face (used GLM-5.2-NVFP4 in real incident investigation). Gartner: Fortune 500s predicted to deploy 150k+ agents by 2028.

Engineering implication

Build agent red-teaming into CI for any agent with tool access; prefer a self-hosted open model for security-sensitive scans to avoid refusal-gating and data egress. Test the tool surface, not the model in isolation. Verdict: Trial the open-source scanner; adopt the "agents-as-systems" testing posture now.
