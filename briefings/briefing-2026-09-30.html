Model Watch
1. GPT-6.1 Sol
MomentumHigh SentimentMixed Production ReadyHigh Hype RiskMedium ConfidenceHigh
What is happening

Released Sept 29, 2026 as an upgrade to GPT-6 Sol: "near-Astra intelligence for a fifth of the price" at $2/$10 per M tokens, with cached input cut to $0.10/M — 95% off standard input and 50% below GPT-6 Sol's cache price. Available in ChatGPT Work and Codex (not yet Chat); API as gpt-6.1-sol. An "Ultrafast" Codex variant (up to 8x faster generation) is coming "in the coming days," per the DevDay recap.

Capabilities & benchmarks

On DeepSWE v1.1 it matches GPT-6 Astra at ~1/5 cost and beats GPT-6 Sol's best by 6.4pts. On GDP.pdf it scores above Opus 5.5-with-fallbacks at <half the cost per task. AutomationBench: +2.2pts over Opus 5.5 at ~1/3 cost. OSWorld 2.0 offline: within 2.1pts of Astra at ~1/7 cost. Terminal-Bench Science 0.1: >2x GPT-6 Sol at max effort ($5.47/task vs $23.21 Opus / $23.80 Astra). Factuality error rate cut ~32% at low effort. Artificial Analysis independently scores it 52 on the Intelligence Index (#10/222 reasoning models, above the 26 median), 1M context, text+image in / text out — but 67.8 t/s (below the 72 median) and a 239s time-to-first-answer-token (vs a 3.9s class median), a steep reasoning-latency tax. No attempts to bypass the automated safety reviewer in alignment evals.

Who is using it

No named production teams in the launch post. HN practitioners report it as a Codex workhorse — one user burns ~1% of a $100/mo plan per 40 min on Sol; another notes "$15 of spend in the past week" for 4-5 investigations/PRs/day. The recurring complaint is compaction frequency on the default 256k Codex context (configurable up to 600k-1M via model_context_window in ~/.codex/config.toml, at 2x price above 250k-400k).

Engineering implication

The cache-price cut is the real news for anyone running Codex agents: persistent-context economics, not headline intelligence, drive agent cost. Pin GPT-6.1 Sol as the cost-tier workhorse and reserve Astra for the hardest ~10%. Watch the Ultrafast variant for the latency gap. Verdict: Adopt for cost-tier coding/professional work; tune compaction thresholds and tool-output filtering to realize the cache savings.

2. Claude Opus 5.5 — taste/efficiency lead hardens
MomentumMedium SentimentPositive Production ReadyHigh Hype RiskLow ConfidenceHigh
What is happening

Now 8 days post-launch, Opus 5.5 holds the AA Intelligence Index top at 58 (several points clear of the field). The signal this cycle is qualitative practitioner evidence rather than benchmarks: a controlled head-to-head on the GPT-6.1 Sol HN thread (user rspeele) ran Astra and Opus 5.5 on the same NURBS-surface-modeling task, same repo, same test suite.

Capabilities & benchmarks

Astra consumed 215% of a week's budget (13h); Opus 5.5 consumed 20% (20h). Opus 5.5 found a bug in a unit test, fixed it, and produced a more complete implementation; Astra adhered strictly to the (buggy) tests, stubbed critical B-spline parts, and gave up. In a blind meta-review where both Astra and Opus reviewers saw both codebases, both converged on preferring the Opus implementation. The practitioner's conclusion: the best use of an Astra budget is as a reviewer/consultant for Opus-written code, not as the primary implementer.

Who is using it

Launch production roster (GitHub, Clio's 18h unattended 6-repo task, Stripe's 40-PR stacked rebase, Optiver, Deloitte, Box, Ramp) remains the strongest this cycle. HN practitioners describe it as a "breath of fresh air" vs Codex compaction — it holds working memory far longer before compacting.

Engineering implication

The differentiator is sustained architectural judgment in long-horizon runs — the axis that resists benchmarking. For hard, open-ended tasks, Opus 5.5 is the primary; use Astra/Sol as cross-model reviewers to counter same-model self-preference bias. Verdict: Adopt as the sustained-judgment tier; pair with a different lab's model for review.

Agent Engineering & AI SDLC
1. OpenAI Dots: always-on "managed agents" (harness separated from compute)
MomentumExplosive SentimentPolarizing Production ReadyMedium Hype RiskHigh ConfidenceHigh
What is happening

Dots (Sept 29) are always-on agents powered by GPT-6 Astra, each with its own cloud computer (Linux + Chrome), reachable via ChatGPT/Slack/Teams and voice. They do "proactive research" in the background (read-only tools), connect to 4,000+ apps via plugins, and use an Auto-review safety system that checks planned actions against instructions/Custom Rules before they run. "Specialist dots" get org-provisioned identity, credentials, and system-of-record access — integrating with Microsoft Agent 365. Rolling out to Pro/Business Premium/Enterprise in eligible markets (excludes EEA, Switzerland, UK); first dot free with plan.

Why it matters

The architectural signal is the "managed agent" pattern: per the safety blog and HN analysis, the dot agent loop does not run inside the sandboxed workspace — "dots run code in environments that are separate from the systems that coordinate their work and enforce key safeguards." This is the first mass-distribution productization of harness-compute separation: the harness (coordinator + Auto-review + safety systems) lives outside the compute sandbox the agent can touch, so a compromised or mistaken agent cannot disable its own checks. It decouples agent lifetime from conversation lifetime — the thesis multiple practitioners identified as the real advance.

Evidence from real teams

Inside-OpenAI dogfooding (Slack bug triage, design→app, planning syncs); an early external tester's dot noticed an unfiled invoice, prepared it, and sent it post-approval. HN's Grok Bot power-users corroborate the always-on pattern: domain-specific agents create trust barriers (separate memory per domain), enable parallel cloud builds, but 2-3x inference spend. Security pushback is severe: a practitioner tested gmail.com in the dot's cloud browser and found an OpenAI-issued MITM certificate (Subject: CN=gmail.com, Issuer: O=OpenAI) — TLS interception is by design for tool operation, but it crystallized the trust concern. EU exclusion was read as a data-protection tell.

Engineering implication

For builders, the durable lesson is the architecture, not the consumer product: separate the agent's execution sandbox from the harness that enforces policy, and put action-gating (Auto-review) outside the agent's reach. Dots itself is a managed, consumer/professional product with serious trust and egress questions — not something to wire into an engineering pipeline. Verdict: Watch the managed-agent pattern; Skip handing production credentials to a first-party always-on agent without read-only/vendable-credential controls.

2. livenerf: pre-registered post-launch drift benchmark
MomentumHigh SentimentPositive Production ReadyMedium Hype RiskLow ConfidenceHigh
What is happening

livenerf (ninjahawk, 584 stars) is a long-running, append-only benchmark answering one question: does a frontier model get quietly worse after launch? Started day-1 on Opus 5.5 (2026-09-24, 2.5 days post-launch), it runs a calibrated 78-question panel once daily for 30 days via headless Claude Code on a Max subscription, built on the UK AI Security Institute's Inspect framework.

Why it matters

This is the methodologically mature version of "silent model-regression tracking" (first seen 2026-09-28). The design is deliberately boring and hostile-reader-proof: pre-registered decision rule (a change is only a change if the 99% interval excludes zero in two consecutive 10-day windows, the effect is ≥3pts, and a control arm — Opus 5 — doesn't move the same way); frozen prompts, pinned CLI, pure-function graders (no LLM judge), exact-match scoring, raw logs forever. Stats follow Anthropic's own "Adding Error Bars to Evals". Critically, the secondary signal is output-token count per sample — "if a model quietly starts thinking less, this is where it shows up first, often before accuracy moves at all." Validation confirmed: effort-low = −62% tokens / −8.3pts accuracy; effort-medium = −26% tokens / −4.2pts. Stated limit: it could not distinguish an Opus 5 swap from Opus 5.5 at 99% — a same-family swap of that size is below the instrument's resolution.

Evidence from real teams

Independent project (not Anthropic-affiliated), but directly addresses the recurring "is Opus 5.5 nerfed yet?" practitioner discourse. Six of 30 days collected as of Sept 29; first result row lands after day 20 (~Oct 14); first possible call ~Oct 24. The methodology is the copyable artifact for any team treating a frontier API as a nondeterministic external dependency.

Engineering implication

Adopt the methodology: pre-register a frozen panel, pin the harness, track per-item paired deltas with clustered SEs, and watch output-token trends as a leading indicator. For production, this is the SDLC analog of regression tests for a dependency you don't control. Verdict: Adopt the pre-registered drift-tracking pattern; Watch the Opus 5.5 series results.

Terminology Tracker
OpenAI Dots (always-on managed agents) — NEW

Definition: OpenAI's Sept 29, 2026 product: always-on agents powered by GPT-6 Astra, each with its own cloud computer, reachable across ChatGPT/Slack/Teams/voice, doing background "proactive research" and connected to 4,000+ apps. The defining architectural property is "managed agents" — the coordinator harness and its safety systems (Auto-review) run outside the sandboxed compute environment the agent can mutate, so the agent cannot disable its own checks. Distinct from a chatbot (decoupled agent lifetime from conversation lifetime), from Codex/ChatGPT Work (long-lived, cross-channel, identity-carrying), and from self-hosted personal assistants (OpenClaw) in that the harness is OpenAI-managed.

Auto-review (separate action-check safety system) — NEW

Definition: The Dots safety architecture: a separate system, running outside the agent's reachable environment, checks every planned write/send/share action against the user's instructions, Custom Rules, and mandatory safety requirements before it executes. If it blocks, it returns the reason to the dot, which can ask for approval, try an alternative, hand the step back, or stop. User approval cannot override core safety requirements. Distinct from per-call permission prompts (class-level, asynchronous, outside the agent's control) and from model-layer refusal (it is an infrastructure-level gate, not a model judgment).

livenerf (pre-registered post-launch drift benchmark) — NEW

Definition: A long-running, append-only, pre-registered benchmark for detecting whether a frontier model degrades after launch. Calibrated panel of "sometimes-right" questions, frozen prompts, pinned CLI, pure-function graders, paired per-item deltas with clustered SEs, and output-token count as a leading indicator. The rigorous instantiation of "silent model-regression tracking" (first seen 2026-09-28) — adds pre-registration, a control arm, and statistical power calculations to the modelregression.com operational pattern.

GPT-6.1 Sol — EVOLVING (first seen 2026-09-23 as "gpt-6 sol and luna")

The cache-price lever — not headline intelligence — is what practitioners flagged as the actual Codex win. AA independently scores it 52 (Index #10/222) but flags a 239s TTFT reasoning-latency tax. An Ultrafast variant (8x faster) is pending.

Claude Opus 5.5 — EVOLVING (first seen 2026-09-21, now 8 sightings)

Holds AA Intelligence Index top at 58. New qualitative practitioner evidence (controlled A/B on a real NURBS task) shows it out-implementing Astra at ~10x lower budget spend and winning a blind cross-model meta-review. The differentiator is sustained architectural judgment in long-horizon runs; the practitioner pattern is Opus-as-implementer + Astra-as-reviewer. Now the subject of livenerf's pre-registered drift series.

Managed agents (harness-compute separation) — NEW

Definition: An agent-deployment architecture, productized by OpenAI Dots, where the agent's coordination loop and policy-enforcement (safety, action-review, monitoring) run in a separate control plane outside the compute sandbox the agent can mutate. The agent gets an ephemeral workspace it can trash; it cannot reach the harness that governs it. Distinct from in-sandbox agents (where the agent and its guardrails share an environment) and from closed harnesses like Claude Code/Codex (products, not an articulated architecture). The first mass-market instance of the "separating harness from compute" thesis tracked since 2026-09-23.

Strategic Implications
Adopt

Pin GPT-6.1 Sol as the cost-tier Codex workhorse and tune compaction thresholds / tool-output filtering to realize the $0.10/M cache savings — the cache price, not headline intelligence, is the adoption lever. Adopt Opus 5.5 as the sustained-judgment primary for hard open-ended tasks, with a different-lab model (Astra/Sol) as cross-model reviewer to counter same-model self-preference. Adopt the livenerf methodology (pre-registered frozen panel, pinned harness, paired deltas, output-token leading indicator) as regression testing for any frontier API you depend on.

Trial

The "managed agent" harness-compute-separation architecture: separate your agent's execution sandbox from the policy-enforcement control plane so the agent cannot disable its own checks, and put action-gating (an Auto-review analog) outside the agent's reach. Trial this as a design pattern in your own agent infrastructure before any first-party always-on agent touches production credentials.
